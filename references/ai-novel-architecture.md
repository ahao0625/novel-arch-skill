# AI 网文创作通用架构方案

> 从实战项目中抽象提炼的通用架构，适用于任何题材的 AI 辅助长篇小说创作。
> 核心设计原则：**模块化、可扩展、AI 上下文友好、全周期覆盖**。

---

### 目录职责说明

| 编号 | 目录 | 核心职责 | 生命周期 | 可选性 |
|:---:|:---|:---|---:|:---:|
| 01 | 世界设定 | 定义故事世界的底层规则 + 反跑偏文件 | 创作前完成，迭代更新 | 必选 |
| 02 | 人物档案 | 角色性格、动机、成长弧 | 创作前完成，持续补充 | 必选 |
| 03 | 故事大纲 | 全书到每章的情节规划 | 创作前完成，可按卷迭代 | 必选 |
| 04 | 时间线 | 时间维度的逻辑校验 | 创作前建立，同步维护 | 推荐 |
| 05 | 伏笔与悬念 | 悬念的埋设与回收追踪 | 随创作动态维护 | 推荐 |
| 06 | 正文内容 | 实际写作成果存储（含卷概述） | 创作中持续产出 | 必选 |
| 07 | 章节索引 | 快速定位和全局概览（按卷拆分） | 随章节更新 | 推荐 |
| 08 | 创作日志 | 记录创作状态、问题、章节摘要缓存 | 每章填写 | 推荐 |
| 09 | 审计报告 | 多维度质量检查结果（按卷分目录） | 阶段性产出 | 推荐 |
| 10 | 创作模板 | 可复用的文档模板（含元数据头部模板） | 初始创建后不变 | 推荐 |
| 11 | 素材库 | 参考资料、图片、考据笔记 | 按需补充 | 可选 |
| 12 | 废弃稿 | 已删除/大幅修改的章节备存 | 按需归档 | 可选 |
| 13 | 数据统计 | 字数曲线、写作进度、频率统计 | 按需更新 | 可选 |

### 文件拆分阈值

| 文件 | 拆分条件 | 拆分方案 |
|:---|:---|---:|
| 人物档案全集.md | 角色数 > 30 | 按阵营分：主角团队.md / 反派阵营.md / 中立势力.md |
| 完整时间线.md | 章节数 > 100 | 按卷分：第X卷时间线.md + 全局总览表 |
| 完整章节索引.md | 章节数 > 100 | 按卷分：第X卷索引.md + 根目录留卷级总索引 |
| 创作日志.md | 章节数 > 100 | 按卷分：第X卷创作日志.md |
| 审计报告 | 文件数 > 10 | 按卷分子目录：09_审计报告/第X卷/ |

### 文件命名规范

| 文件类型 | 命名规则 | 示例 |
|:---|---:|:---:|
| 正文文件 | `第X章.md`（不要加书名前缀） | `第1章.md` |
| 卷内概述 | `卷概述.md` | `卷概述.md` |
| 设定文件 | `{描述}.md`（不用前缀） | `总纲.md`、`地理与势力.md` |
| 卷级文件 | `第X卷{描述}.md` 或 `第X卷/{描述}.md` | `第1卷·章节纲要.md` |
| 审计报告 | `第X卷审计报告（第X-X章）.md` | `第一卷审计报告（第1-10章）.md` |
| 快照文件 | `设定快照_第X卷.md` | `设定快照_第一卷.md` |
| 日志文件 | `第X卷创作日志.md` | `第一卷创作日志.md` |
| 章节索引 | `总索引.md` + `第X卷索引.md` | `总索引.md`、`第一卷索引.md` |
| 根级文件 | `{描述}.md` | `创作工作流.md`、`项目配置.md` |

> **核心规则**：正文和设定文件不加书名前缀（避免文件名过长），只有需要跨项目区分时才加。文件名保持「所见即所得」，不需要额外解释。

### 项目配置模板

`项目配置.md` 是项目的"系统提示词"——AI 每次对话开始时应自动读取的固定上下文。在首次搭建项目目录时填写此文件。

```
# 项目配置

## 项目信息
- 书名：{书名}
- 类型：{玄幻/都市/科幻/历史/悬疑/言情}
- 目标字数：200 万字
- 单章字数：2000-3000 字
- 总卷数：9 卷
- 核心主题：{一句话提炼}

## AI 行为指令
- 输出语言：中文
- 每次创作前必须读取：01_世界设定/设定速查锚点.md
- 每章完成后必须填写：08_创作日志/{本卷}创作日志.md
- 每次审计前必须读取：01_世界设定/红线清单.md
- 角色档案读取规则：仅读取本章活跃角色的档案，不读全集

## 写作风格锚点
- 文风取向：{简练/细腻/热血/幽默/写实}
- 对标参考：{可选参考作品}
- 禁用词汇：{可选自定义禁词}
- 去 AI 痕迹策略：参照创作工作流中的禁令和限频词

## 项目约定
- 每卷完成后需生成设定快照
- 设定变更后须更新设定变更日志
- 章节元数据头部为必填项
```

#### 配置文件的使用方式

```
在 AI 对话 / IDE 提示词中引用本项目配置：
"请根据项目配置.md 中的行为指令进行创作。"
```

> 项目配置与创作工作流的分工：**工作流**描述"怎么做"（流程步骤），**项目配置**描述"是什么"（项目元信息 + AI 行为约束）。

### 优化点总览

> **优化点**：
> - 将「章节标题」改为「章节索引」，从纯标题存储升级为含字数/状态的导航页，且**按卷拆分**避免单文件膨胀
> - 新增「创作模板」目录，解决"每次写章节纲要/审计报告都要手打模板"的效率问题
> - 将「伏笔体系」改为「伏笔与悬念」，覆盖更广的叙事手法
> - 「世界设定」替代「世界观设定」，兼容都市/悬疑/历史等非幻想题材
> - **01_世界设定/** 下新增 4 个守御文件（速查锚点/变更日志/快照/红线清单）
> - **06_正文内容/** 每卷纳入 `卷概述.md` 标准化卷内结构
> - **07_章节索引/** 和 **08_创作日志/** 按卷拆分，避免 2000 章后单文件无法读取
> - **09_审计报告/** 按卷分子目录，方便管理
> - 新增可选目录 **11_素材库/**、**12_废弃稿/**、**13_数据统计/**
> - 明确 **文件拆分阈值**：当角色数 > 30、章节数 > 100 时的拆分指引
> - 统一 **文件命名规范**，正文和设定文件不加书名前缀
> - 提供 **项目配置模板**，作为项目级 AI 行为指令配置文件
> - 明确 **创作工作流与架构方案的关系**：工作流内容可提取为独立根级文件

## 二、创作工作流（通用版）

### 阶段一：初始化

```
项目启动
  ├── 明确：类型、目标字数、单章字数
  ├── 确定核心主题（一句话提炼）
  ├── 搭建 01~10 目录结构
  ├── 填充模板文件（总纲/人物/大纲骨架）
  └── 录入 10_创作模板/ 下的所有模板
```

### 阶段二：创作前（读文件）

每次开始写作前，AI 需要读取的**核心上下文**按优先级分三层：

```
🔴 必读（每次必须加载）
  ├── 01_世界设定/设定速查锚点.md    # 核心规则速览（极简版）
  ├── 01_世界设定/总纲.md            # 项目概览（需要详细设定时）
  ├── 01_世界设定/红线清单.md        # 不可触碰的底线（创作前确认）
  ├── 02_人物档案/人物档案全集.md     # 当前章节涉及角色的档案（选择性读取）
  ├── 03_故事大纲/第X卷·章节纲要.md   # 本章的详细规划
  ├── 07_章节索引/第X卷索引.md        # 本章所在卷的章节索引（前后章标题及状态）
  └── 08_创作日志/第X卷创作日志.md    # 本卷创作记录、未解决问题

🟡 轮读（每 10 章轮换一次，或写跨卷章节时）
  ├── 01_世界设定/*.md               # 完整设定核查
  ├── 04_时间线/完整时间线.md         # 时间轴核查
  └── 05_伏笔与悬念/伏笔与揭秘体系.md # 悬念状态同步

🟢 按需（剧情涉及时才读）
  ├── 06_正文内容/第X卷/之前章节.md   # 跨章连贯性核验
  ├── 09_审计报告/第X卷/*.md          # 历史问题回顾
  ├── 01_世界设定/设定快照_第X卷.md    # 按卷快照（跨越卷时必读）
  └── 08_创作日志/卷内章节摘要缓存.md  # 卷内各章摘要（跨章连贯性）
```

> **优化点**：引入 **AI 上下文预算管理**——不是所有文件每次都要读。通过优先级分层，在 AI 上下文窗口有限的情况下，最大化有效信息密度。

#### 创作前检查清单（通用版）

```
【卷创作前】
□ 本卷起止状态（境界/阶段/等级）
□ 本卷核心事件（对应大纲）
□ 本卷必埋/必收的伏笔
□ 重要配角出场安排
□ 主要人物情绪弧转折点

【章节创作前】
□ 本章情绪曲线（低开高走/持续紧张/先抑后扬等）
□ 章末钩子类型（悬念埋设/暗示/回收/升级）
□ 涉及角色的性格和心理状态校验
□ 时间线校验（季节/年龄/阶段）
□ 空间位置校验（所在场景/区域）
□ 能力/资源范围校验（是否超纲）
```

### 阶段三：创作中（写作原则）

四阶段写作流程（通用化）：

```
┌─────────────────────────────────────────────────────┐
│  ① 深度分析                                          │
│  ├─ 本章核心冲突/主题定位                             │
│  ├─ 情绪曲线设计（起承转合）                          │
│  └─ 提取关键要素：本次要调动的人物/设定/伏笔          │
├─────────────────────────────────────────────────────┤
│  ② 结构规划                                          │
│  ├─ 段落节奏规划（紧张场景短句、抒情场景长句）        │
│  ├─ 亮点设计（反转/伏笔/金句/共鸣点）                │
│  └─ 字数预算分配（各段落占比）                        │
├─────────────────────────────────────────────────────┤
│  ③ 优质撰写                                          │
│  ├─ 开篇抓人：悬念/冲突/异常切入（不写"天亮了"）     │
│  ├─ 主体扎实：细节支撑、五感描写、行为替代分析        │
│  ├─ 结尾有力：情绪升华/动作收束/悬念留白             │
│  └─ 文笔校验：删冗余、用精准动词、画面感            │
├─────────────────────────────────────────────────────┤
│  ④ 自我质检                                          │
│  ├─ 逻辑自洽？人物不OOC？节奏合适？                  │
│  ├─ 章末钩子是否已达预期效果？                        │
│  └─ 本章是否是"信息增量章节"而非"灌水章节"？        │
└─────────────────────────────────────────────────────┘
```

### 阶段四：创作后（存稿 + 日志 + 审计）

```
完成章节
  ├── 1. 保存正文 → 06_正文内容/第X卷/第X章.md
  │
  ├── 2. 字数核验
  │   └─ 执行：wc -m 文件路径
  │   └─ 标准：≥ 目标字数（如 2000 字），超标则精简
  │
  ├── 3. 填写日志 → 08_创作日志/第X卷创作日志.md
  │   ├─ 章号、日期、字数
  │   ├─ 完成度（按规划/部分偏离/大幅调整）
  │   ├─ 本章小结（写了什么/偏离了什么/问题）
  │   └─ 伏笔状态（新埋了哪些/收了哪些）
  │
  ├── 4. 更新章节摘要缓存 → 08_创作日志/卷内章节摘要缓存.md
  │   └─ 用 1-3 句话概括本章核心事件
  │
  ├── 5. 更新伏笔 → 05_伏笔与悬念/伏笔与揭秘体系.md
  │
  ├── 6. 更新章节索引 → 07_章节索引/第X卷索引.md
  │
  ├── 7. 阶段性审计（每 10 章触发）
  │   └─ 按模板输出审计报告 → 09_审计报告/第X卷/
  │
  ├── 8. 更新红线清单（如有新增红线）
  │   └─ 01_世界设定/红线清单.md
  │
  ├── 9. 更新设定变更日志（如有设定变更）
  │   └─ 01_世界设定/设定变更日志.md
  │
  └── 10. 卷结束时 → 生成设定快照存档
      └─ 01_世界设定/设定快照_第X卷.md
```

> **实操指引**：将本章「二、创作工作流」的全部内容提取为独立文件 `创作工作流.md`，放置在项目根目录作为 SOP 入口。这保证 AI 每次对话开始时只要读这一个文件就能获取完整的工作流指令，无需反复翻阅架构方案文档本身。

## 三、AI 上下文管理策略

这是本架构的核心优化。长篇小说创作的最大瓶颈不是写作能力，而是 **AI 上下文窗口对长篇记忆的物理限制**。

### 3.1 上下文预算分配

以 8K~16K token 上下文为例：

| 上下文区域 | 预算占比 | 内容 | 战术 |
|:---:|:---:|:---|---:|
| 固定骨架 | ~20% | 类型规则、写作风格锚点、创作原则 | 写入总纲或工作流文件，每次必读 |
| 当前卷上下文 | ~35% | 本卷大纲、卷内已有章节摘要 | 每次写入新章前更新摘要缓存 |
| 人物与设定 | ~25% | 本章涉及角色的完整档案、相关设定 | 按需选择性读取，不读全集 |
| 质量指令 | ~20% | 质检要求、去AI痕迹规则、限频词 | 写入工作流，每次创作前加载 |

### 3.2 章节摘要缓存

```
核心思想：AI 记不住 40 章的所有细节，但可以记住 40 章的摘要。

在 08_创作日志/ 中维护：
- 一个「卷内章节摘要缓存」，每章用 1-3 句话概括核心事件
- 每次写新章前，把这份摘要作为上下文输入
- 作用：跨章连贯性 + 伏笔回指 + 人物状态追踪
```

### 3.3 文件引用约定

```
在正文中使用「标记式引用」，确保 AI 能准确回指设定：

示例：
- 「（参见 02_人物档案：林昭 #性格）」→ 告知 AI 参照人物性格
- 「（伏笔 A-2，埋于第 3 章）」→ 标记伏笔位置
- 「（时间线：第 2 年秋）」→ 标注时间节点

作用：给 AI 一个明确的回指锚点，减少"它知道但这个上下文没带进来"的问题。
```

## 四、反跑偏与设定守御体系

> 架构的核心目标：**AI 读了不跑偏，设定写了不丢失**。
> 以下 7 个机制构成闭环——创作前锁定锚点、创作中排除干扰、创作后变更追踪、跨阶段自动核验。

---

### 4.1 章节元数据头部

每章正文开头嵌入结构化元数据块，AI 打开文件后**第一眼就准确定位**，无需从行文中推测当前状态。

```
---
章号: 87
卷: 第三卷
时间: 主角 19 岁秋（距离开篇 2 年）
地点: 北境冰原
主角状态: 筑基中期，重伤未愈，法力残余 30%
活跃角色: 林昭、柳如是（本卷女主角）、陈长老
本章核心: 北境秘境探索，发现仙庭禁制线索
前情提要: 第 86 章末尾，林昭被冰龙追杀跌落悬崖
---
```

#### 元数据字段说明

| 字段 | 必填 | 作用 |
|:---|:---:|:---|
| 章号 | ✅ | 唯一标识，AI 据此定位上下文 |
| 卷 | ✅ | 区分所在卷，避免跨卷设定混用 |
| 时间 | ✅ | 距离开篇多久/故事内时间，防时间线混乱 |
| 地点 | ✅ | 当前场景所在区域 |
| 主角状态 | 推荐 | 等级/健康/装备等核心状态 |
| 活跃角色 | 推荐 | 本章出场角色清单，AI 据此选择性读档案 |
| 本章核心 | ✅ | 一句话锁定本章目的，防偏题 |
| 前情提要 | 推荐 | 上一章末尾的状态承接，防情节断裂 |

> 元数据写好后**随正文一起保存**。后续审计环节可通过元数据快速回查时间线一致性。

---

### 4.2 设定速查锚点

在 `01_世界设定/` 下维护一个**极简文件**（不超过 1 页），与详细设定分开。AI 创作前只需读这一页，无需遍历整个设定目录。

```
# 设定锚点速查（当前状态）
> 每次卷更新/重大设定变更时同步刷新。AI 每次写作前首选阅读此文件。

## 当前状态
- 主角: XXX | 当前等级: XXX | 所在地: XXX
- 本卷: 第 X 卷 | 本卷核心矛盾: XXX
- 当前时间: 开篇后 X 年 X 月

## 势力关系（当前）
- 势力 A → 势力 B: 敌对
- 势力 C → 势力 D: 同盟
- 主角 → 势力 A: 依附

## 近况变化（最近 20 章内新揭露/变更的设定）
- [事件/设定] → 影响说明
- [事件/设定] → 影响说明

## 活跃悬念（待回收，按紧急度排序）
- [编号] 描述 → 已埋 X 章
- [编号] 描述 → 已埋 X 章
```

#### 速查锚点的维护节奏

| 时机 | 动作 |
|:---|---:|
| 每章创作前 | 读取速查锚点（作为前置上下文） |
| 每卷结束 | 完整刷新一次锚点 |
| 设定变更时 | 即时更新受影响字段 |

> **设计思路**：详细设定是"百科全书"，速查锚点是"作战地图"。AI 写作前读的是地图，不是整本百科全书。

---

### 4.3 排除指令

在创作前明确告知 AI **不需要关注的范围**，比告诉它关注什么更省上下文——排除法可以减少 AI 的思维干扰。

```
本章排除指令：
□ 不需要关注的势力：仙庭、天魔宗（本章不涉及）
□ 不需要关注的角色：[角色 A]、[角色 B]（未出场）
□ 不需要关注的伏笔：F-3、G-1、H-2（未到回收时机）
□ 不需要关注的事件：[事件名]（后续章节再处理）
□ 不需要检索的设定：[某规则体系]（本章用不到）
```

#### 作用原理

```
没有排除指令时：
  AI 读取了所有设定 → 脑补了不必要的关联 → 把无关势力/角色写进正文 → 偏离大纲
有排除指令时：
  AI 明确知道自己不需要管什么 → 上下文聚焦 → 写作精确度提升
```

> 排除指令随创作前检查清单一起执行，可作为清单中的一项勾选。

---

### 4.4 设定变更日志

在 `01_世界设定/` 下维护一个**设定变更日志**，追踪每项设定的修改历史，防止 AI 新旧版本混用。

```
# 设定变更日志

| 版本 | 日期 | 变更内容 | 变更原因 | 影响范围 |
|:---:|:---:|:---|---:|:---:|
| v1.0 | 初始 | 基础设定建立 | — | — |
| v1.1 | YYYY-MM-DD | 修改主角境界上限 | 大纲调整 | 第 X 卷及之后 |
| v1.2 | YYYY-MM-DD | 新增势力"天河宗" | 世界观扩展 | 第 X 卷 |
| v1.3 | YYYY-MM-DD | 调整[角色]与[角色]关系 | 情节合理化 | 第 X~X 章 |
```

#### 读取规则

```
AI 读变更日志的规则：
1. 取最高版本号 = 当前有效状态
2. 日志中标注「影响范围」的变更，只在对应范围生效
3. 旧版本设定不再使用，除非明确回滚
```

> 配合「设定快照存档」（4.5）使用：变更日志记录"改了什么"，快照记录"现在长什么样"。

### 4.5 设定快照存档

每完成一卷/每 10 章，将当前所有核心设定的**完整状态**打包成一个快照文件，存入 `01_世界设定/`。

```
# 设定快照：第 X 卷结束时（第 1-60 章）
快照时间: YYYY-MM-DD
基于版本: v1.3

## 主角状态
- 姓名: XXX
- 等级: XXX（已解锁能力清单）
- 装备: [清单]
- 人际关系: [关键关系列表]

## 世界观当前状态
- 已揭示的秘密: [清单]
- 未揭示的秘密: [清单]
- 势力关系现状: [摘要]

## 已完成事件
- 本卷核心事件完成情况
- 主角成长里程碑

## 活跃伏笔
- [编号] 描述 → 埋设章节 → 预计回收章节

## 待办事项（下卷需要处理的）
- [事项]
```

#### 为什么需要快照

```
不使用快照的风险：
  写第 200 章时，AI 需要从 01_世界设定/ 的多个文件中
  拼凑"当前状态"——效率低，且容易遗漏变更。

使用快照：
  AI 只需读一份快照文件，就获得"截至第 X 卷结束时的完整设定图景"。
  后续写作以此快照为准，大大降低上下文噪音。
```

> 快照是**增量不替换**的——上一卷的快照保留作为历史存档，新快照覆盖最近状态。

### 4.6 不可践踏的红线

在 `01_世界设定/` 下维护一个**红线清单**，明确标注哪些是绝对不允许 AI 触碰或修改的刚性规则。

```
# 不可践踏的红线
> AI 在任何情况下不得违反以下规则。审计时如果检测到红线被触碰，必须立即修正。

## 角色红线
- [角色 A] 不会背叛 [角色 B]（核心关系不可动摇）
- [角色 A] 与 [角色 B] 有血缘关系，感情线仅限亲情
- 主角在全书完结前不会死亡

## 设定红线
- [某底层规则] 不能被推翻（世界观基石）
- [某力量体系] 的等级上限不可被打破
- [某反派] 的动机不可被洗白

## 情节红线
- [某核心事件] 的发生顺序不可调换
- [某真相] 必须在第 X 卷之后才揭露，提前揭露视为违规
```

#### 红线在审计中的角色

```
红线与审计维度的关系：
  日常审计维度（第 5 章）→ 检查"写得好不好"
  红线清单 → 检查"有没有违反底线"
  红线违规 = 必须重写，不能妥协
```

> 红线的典型来源：创作前作者自己定下的"铁则"，或者读者反馈中暴露出的不可接受的设定变动。

```python
功能:
  1. 时间线冲突检测

  4. 伏笔超期未回收告警
  5. 限频词超标检测
  6. 红线违规检测
  7. 章节元数据完整性检查
"""

# 核心检测逻辑（示例框架）

    "时间线冲突": lambda: detect_timeline_conflicts(),

```

#### 建议实现的检测项目

| 检测项 | 检测内容 | 输出格式 |
|:---|---:|:---:|
| 时间线冲突 | 同一时间点出现了两个不同描述 | 🔴 冲突位置 + 冲突描述 |
| 年龄异常 | 角色年龄与时间线推算不符 | 🔴 角色 + 错误年龄 |
| 等级超纲 | 角色使用了未解锁等级的能力 | 🔴 章节 + 超纲能力 |

| 限频词超标 | 单章限频词出现频率 > 1次/3000字 | 🟡 词汇 + 出现次数 |
| 红线违规 | 检测到红线清单中的禁止行为 | 🔴 红线 + 违规位置 |
| 元数据缺失 | 章节缺少必填元数据字段 | 🟢 缺少的字段列表 |

> 脚本应设计为**增量检测**（只检测新写的章节），避免每次全量扫描 200 万字的正文。

## 五、质量保障体系

### 5.1 日常审计维度

| 层级 | 维度 | 说明 |
|:---:|:---|---:|
| 🔴 致命 | 设定冲突 | 规则/时间线/空间是否正确 |
| 🔴 致命 | 角色 OOC | 性格/说话/决策是否符合档案 |
| 🔴 致命 | 能力超纲 | 是否使用了未解锁的能力/资源 |
| 🟡 警告 | 情节推进 | 本章是否有实质进展（核心） |
| 🟡 警告 | 悬念健康 | 埋设的悬念是否 >10 章未提及 |
| 🟡 警告 | 节奏监控 | 连续多章是否节奏单一（紧张/悠闲） |
| 🟢 提示 | 配角功能 | 配角出场是否有不可替代的作用 |
| 🟢 提示 | 格式规范 | 对话/段落/标点是否统一 |

### 5.2 去 AI 痕迹策略（通用版）

#### 用词管控

```
限频词（每 3000 字 ≤ 1 次）：
不由得、脑海中、心头一震、猛然间、缓缓、淡淡、竟然、仿佛、忽然、似乎

建议替换方向：
- "他缓缓站起" → "他站起身，膝盖咔嗒一声"
- "她忽然明白" → "她脚步一顿，瞳孔微缩"
- "他脑海中闪过一个念头" → "他想起——"
```

#### 五条禁令（通用化）

1. **禁情绪形容词堆砌**——悲伤/痛苦/绝望不同框出现，用行为展示情绪
2. **禁分析式描写**——动机用行为暗示，不要写"因为他想到……所以……"
3. **禁连续情绪转折**——单段落内不超过两次情绪变化
4. **禁把方法写进正文**——修炼/学习/推理过程用场景和结果暗示
5. **禁同一意象跨章重复**——每章的标志性意象必须不同

#### 结构去模板化

| 位置 | 错误写法 | 正确写法 |
|:---:|:---|---:|
| 开篇 | "天刚蒙蒙亮，XXX 从床上坐起" | 事件中间切入，如"第三剑劈下来时，他才想起今天忘了上香" |
| 结尾 | "他眼中闪过一丝精光，喃喃道：____" | 动作收束/对话留白/"门推开了，走进来一个意想不到的人" |
| 战斗 | "施展 XXX 招式，威力惊人" | 感官压力替代罗列——"空气被抽干，汗毛根根竖起" |
| 感悟 | "他突然明白了" | 后续行为展示——他转头走向了与计划相反的方向 |

## 八、架构设计原理（为什么要这样设计）

```
这个架构回答了三个核心问题：

1. AI 记不住怎么办？
   → 分层上下文管理 + 章节摘要缓存 + 外部存储分担记忆
   → 每次只输必要信息，不输全集

2. 写了 200 万字后怎么不崩？
   → 目录模块化，每一层只负责一件事
   → 审计体系在设定跑偏前拉回轨道
   → 红线清单守住底线，快照存档兜底

3. 不同题材怎么复用？
   → 目录名可适配 → 审计维度可扩展 → 工作流不变
   → 只换"皮肤"不换"引擎"

4. 怎么确保 AI 不跑偏、设定不丢失？
   → 前置锚点锁定方向（章节元数据 + 设定速查）→ 排除指令消除噪声
   → 变更日志追踪版本 → 快照存档定期凝固
   → 红线清单守住底线 → 核验脚本自动化扫描
   → 以上 7 个机制形成一个完整的「守御闭环」
```
